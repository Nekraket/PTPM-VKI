## Варианты проектов:

### 🔹 Вариант 1. Вычисление вида треугольника и координат его вершин
Метод вычисляет вид геометрической фигуры по трем сторонам и рассчитывает координаты трех её вершин для последующей отрисовки в поле размером `100x100 px`.

#### Входные данные
* `строка1` — длина стороны A.
* `строка2` — длина стороны B.
* `строка3` — длина стороны C.

⚠️ **Ограничения:** Все три строки должны представлять вещественные положительные числа точности `float`. Некорректные входные данные обрабатываются как ошибочные без аварийного завершения программы.

#### Выходные данные
1. **Тип треугольника (String):** `равносторонний`, `равнобедренный`, `разносторонний`, `не треугольник` *(или пустая строка для нечисловых данных)*.
2. **Координаты вершин (Массив кортежей):** Список из 3 элементов вида `(int, int)`.
   * При ошибочных числовых данных координаты сбрасываются в `(-1, -1)`.
   * При невалидных (нечисловых) данных координаты сбрасываются в `(-2, -2)`.

### 🔹 Вариант 2. Проверка данных пользователя при регистрации
Метод осуществляет комплексную валидацию учетных данных при регистрации пользователя.

#### Входные данные
* `Строка1` — Логин (может быть в формате телефона `+x-xxx-xxx-xxxx`, email или обычной строки).
* `Строка2` — Пароль.
* `Строка3` — Подтверждение пароля.

#### ⛔ Правила валидации (Ограничения)
* **Логин (телефон/email):** Валидация согласно стандартным маскам.
* **Логин (строка):** Минимум 5 символов, только латиница, цифры и знак подчеркивания `_`.
* **Запрещенные логины:** Не должен совпадать с логинами из предустановленного черного списка.
* **Пароль:** Минимум 7 символов. Обязательно содержит только кириллицу, цифры и спецсимволы. Должна быть минимум одна буква в верхнем и нижнем регистре, одна цифра и один спецсимвол.
* **Совпадение:** Пароль и подтверждение пароля должны быть идентичны.

#### Выходные данные
* `Строка1` (Результат) — `True` (успех) или `False` (ошибка).
* `Строка2` (Сообщение) — Пустая строка при успехе или текст с описанием причины неуспеха *(предусмотрено не менее 10 различных причин)*.

## Требования к логированию
Программа реализует сквозное логирование всех ключевых событий параллельно в **файл** и в **консоль**.

| Тип события | Что логируется |
| :--- | :--- |
| **Успешный запрос** | Дата и время, параметры запроса, результат вычислений/регистрации. |
| **Неуспешный запрос** | Дата и время, параметры запроса, текст ошибки *(включая трассировку стека исключений/traceback при сбое)*. |

## ⚙️ Руководство: Работа со стандартным логгером Python (`logging`)

### 1. Установка
Модуль `logging` является частью стандартной библиотеки Python. Дополнительная установка через `pip` **не требуется**. Но требуется создание папки Logs в директории с файлом в котором написан конфиг и запускается логгер.

### 2. Настройка
В самом начале выполнения программы (в главной точке входа `main.py` **в методе Main**) необходимо импортировать модуль и сконфигурировать базовые обработчики для одновременного вывода в консоль и файл.

```python
import logging
import sys

# Шаблон строки лога (аналог template в Serilog)
# Содержит: время, уровень (до 7 символов для выравнивания), имя логгера и сообщение
log_format = "%(asctime)s | [%(levelname)-7s] | %(message)s"
date_format = "%Y-%m-%d %H:%M:%S"

# Базовая настройка корневого логгера
logging.basicConfig(
   level=logging.DEBUG,  # Минимальный уровень логирования (аналог MinimumLevel.Debug)
   format=log_format,
   datefmt=date_format,
   handlers=[
      logging.StreamHandler(sys.stdout),  # Настройка логирования в консоль
      logging.FileHandler("Logs/file_txt.log", encoding="utf-8")  # Настройка логирования в файл
   ]
)

logging.info("Логгер успешно сконфигурирован")
logging.info("Приложение запущено")
```

* **`format`** — задает строку-шаблон логируемых сообщений.
* **`level`** — задает минимальный порог важности (`logging.DEBUG`), ниже которого сообщения будут игнорироваться.

### 3. Уровни логирования и методы
Для вызова логов разного уровня используются соответствующие методы объекта `logging` (или кастомного логгера):

| Метод | Для чего обычно используется |
| :--- | :--- |
| `logging.debug()` | Самый подробный уровень. Используется для отладки, логирования и промежуточных состояний переменных. |
| `logging.info()` | Логирование основных событий, описывающих штатную работу или простые информационные сообщения. |
| `logging.warning()` | Сигнализирует о событиях, которые могут привести к ошибкам в будущем или о неожиданном поведении программы. |
| `logging.error()` | Логирование ошибок, возникших в процессе работы. Это ожидаемые или перехваченные ошибки. |
| `logging.critical()` | Критические ошибки и падения. Сигнализирует о том, что программа или отдельный модуль не могут продолжать работу. |

### 4. Пример использования в коде

```python
import logging

try:
    a = 10
    for b in range(0, 3):
        logging.info(f"Итерация b = {b}")
        
        if b == 0:
            logging.warning("Внимание, переменная b инициализирована нулем!")
            
        logging.debug(f"Выполнение деления {a} на {b}")
        result = a / b
        logging.info(f"Деление {a} на {b} равно {result}")

except ZeroDivisionError as ex:
    # Метод logging.exception() автоматически прикрепляет traceback (стек ошибки)
    logging.error("Что-то пошло не так...")
    logging.exception("Заход в блок обработки исключения:")
```
